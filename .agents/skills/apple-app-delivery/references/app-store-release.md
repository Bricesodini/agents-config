# App Store release

Read this for an official public release. This path starts after a valid App Store-signed build exists; it is not implied by TestFlight.

Before submission, inspect and resolve the public-release requirements for the exact app and platform: version metadata, screenshots where required, age rating, privacy information, export compliance, pricing/availability, content rights, review contact, and release mode. Do not invent store copy, price, territories, privacy answers, or release timing; obtain the user’s decision where it is missing.

Submit the selected build for App Review only when the user authorized submission. A request to submit does not authorize public release. Before releasing, state whether the requested mode is automatic, manual, or scheduled and confirm it with the user. Read back the resulting App Store version and release state.
